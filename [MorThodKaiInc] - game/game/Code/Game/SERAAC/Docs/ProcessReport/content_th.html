บทที่ 1แผนการดำเนินงาน

1.1 วิธีวางแผนและเครื่องมือที่ใช้

ทีมวางแผนงานแบบ Agile แบ่งงานทั้งเทอมเป็น 4 Sprint (Sprint ละ 2 สัปดาห์) เอกสารวางแผนทั้งหมดเขียนเป็นไฟล์ Markdown และเก็บไว้ใน repository บน GitHub ในโฟลเดอร์ `docs/agile` ได้แก่ Product Backlog (รายการ User Story ทั้งหมดพร้อมลำดับความสำคัญแบบ MoSCoW) Sprint Backlog (Story ที่จะทำในแต่ละ Sprint) Sprint Plan (ผู้รับผิดชอบ ค่าประมาณงาน และสถานะของแต่ละงาน) และบันทึกการประชุม Stand-up รายสัปดาห์

การติดตามงานในแต่ละวันทำผ่าน Discord โดยสมาชิกแจ้งความคืบหน้า ส่งภาพหรือไฟล์ที่ทำเสร็จ และนัดประชุมเสียงเมื่อต้องตัดสินใจร่วมกัน จากนั้นจึงนำสถานะไปอัปเดตใน Sprint Plan

ไฟล์ทั้งหมดของเกมจัดเป็นโฟลเดอร์ตามประเภท ภาพและเสียงอยู่ในโฟลเดอร์ `Art/` และ `Audio/` ซึ่งเกมโหลดตอนรัน ผู้ออกแบบจึงเปลี่ยนภาพหรือเสียงได้โดยแค่วางไฟล์ใหม่ทับไฟล์เดิม ไม่ต้องแก้โค้ด ไฟล์ตั้งค่าที่ใช้บ่อย เช่น พื้นหลังฉากต่อสู้และเอฟเฟกต์หมอก เป็นไฟล์ JSON ที่แก้แล้วเห็นผลขณะเกมยังเปิดอยู่

3.4 สรุปผลการใช้ช่องทางสื่อสารและแบ่งปันไฟล์

การใช้ Discord เป็นช่องทางหลักได้ผลดีกับทีม เพราะสมาชิกทุกคนใช้อยู่แล้ว ส่งภาพและไฟล์ได้เร็ว ให้ความเห็นงานภาพได้ทันที และประชุมเสียงได้โดยไม่ต้องนัดสถานที่ งานภาพ เสียง และบทนำของเกมในช่วงหลังจึงคืบหน้าได้เร็ว

ปัญหาที่พบคือไฟล์ที่ส่งในแชตค้นหายากเมื่อเวลาผ่านไป บางครั้งไม่แน่ใจว่าไฟล์ใดเป็นฉบับล่าสุด และไฟล์ขนาดใหญ่ เช่น ไฟล์เสียงชุดใหญ่หรือไฟล์ Blender ส่งผ่าน Discord ไม่สะดวก แนวทางที่ทีมใช้ต่อไปคือปักหมุดไฟล์ฉบับล่าสุดในแต่ละช่อง ตั้งชื่อไฟล์ตาม naming convention ในเอกสาร GDD และนำไฟล์ที่ผ่านแล้วเข้า repository ทันที

4.1 การใช้ Git และ GitHub

โปรเจกต์ใช้ Git ร่วมกับ GitHub (repository `rastrelligr/morthodkai-inc-aac-rip-off-`) โดยมี branch `main` สำหรับเวอร์ชันที่เสถียร และ branch `dev` สำหรับรวมงานระหว่างพัฒนา สมาชิกแต่ละคนแตก branch ของตัวเองจาก `dev` ตามรูปแบบ ชื่อเล่น/งาน/บทบาท แล้วรวมกลับผ่าน merge หรือ Pull Request ข้อความ commit ใช้รูปแบบ conventional commits เช่น `feat:` `fix:` `docs:` `chore:`

4.3 ข้อสังเกตเกี่ยวกับการใช้ version control

ช่วงเดือนกันยายนทีมใช้ GitHub อย่างสม่ำเสมอ ทั้งการแตก branch การ merge และการแก้ conflict ร่วมกัน แต่หลังจากเปลี่ยนเป็นดีไซน์ใหม่ปลายเดือนกันยายน งานส่วนใหญ่ทำบนเครื่องของผู้ทำงานหลักและแชร์ผ่าน Discord แทน ประวัติบน GitHub จึงไม่ได้สะท้อนงานในช่วงเดือนตุลาคมถึงต้นเดือนพฤศจิกายน งานทั้งหมดในช่วงนั้นถูกรวมเข้า repository อีกครั้งพร้อมกับการออกเวอร์ชัน v0.1.3

บทเรียนที่ได้คือควร commit และ push งานเป็นระยะแม้งานยังไม่เสร็จ เพื่อให้มีจุดย้อนกลับและให้สมาชิกคนอื่นเห็นความคืบหน้า ไฟล์เสียงและภาพขนาดใหญ่ควรตัดไฟล์ที่ไม่ได้ใช้ออกก่อน (ในเวอร์ชันนี้ลดโฟลเดอร์เสียงจากประมาณ 4.3 GB เหลือประมาณ 420 MB) หรือใช้ Git LFS

4.4 Release เวอร์ชันส่งงาน

เวอร์ชันส่งงานติด tag `v0.1.3` บน branch `dev` และสร้างเป็น Release บน GitHub ชื่อ Prototype build v0.1.3 เนื้อหาหลักของเวอร์ชันนี้มีดังนี้

  • บทนำ 5 บท ตั้งแต่ห้องของ Relle การซ้อมต่อสู้ในเครื่องจำลอง Airlift Platform และ The Sanctum ไปจนถึงด่าน Fallen Academy และบอส Wyvern
  • บทสนทนาแบบ Visual Novel พร้อมประวัติข้อความ เล่นอัตโนมัติ และข้าม
  • แผนที่จาก Tiled พร้อมระบบชน จุดโต้ตอบ และ NPC
  • Naomi เป็นตัวละครที่เล่นได้ และสไปรต์ใหม่ของ Relle และ Naomi
  • เพลงและเสียงประกอบ หมอก ฝุ่น และเมฆ หน้าจอโหลด และหน้า Options สำหรับปรับเสียง

วิธี build รัน และเล่นเกม อธิบายไว้ในไฟล์ `README.md` ที่รากของ repository
